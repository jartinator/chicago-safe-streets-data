# Agentic-layer inventory — as built (contract v1.16, main as of 2026-07-22)

*Stimulus document for study #1 (the agentic layer). This is the factual
record of what OYL ships **today** for AI-agent consumers. Every subsequent
artifact in this study (feasibility briefs, audit protocol, interviews,
synthesis) treats this file as the single description of the as-built layer.
Nothing here is proposal; it is inventory.*

Live site origin: `https://jartinator.github.io/chicago-safe-streets-data/`

---

## 1. What exists

### 1.1 The static API (`/api/v1/`)

A static, versioned, **additive** JSON namespace generated by
`pipeline/emit_api.py` from the same committed `site/data/` contract as the
human site. Not a live service: nothing to authenticate, rate-limit, or keep
running; rebuilt weekly by the data-refresh workflow. Existing keys never
change shape without a `CONTRACT_VERSION` bump (currently **1.16**).

Top-level endpoints (9):

| Path | ~bytes | Content |
|---|---|---|
| `citywide.json` | 17.5k | Monthly citywide crash trend, headline findings, mileage/protected-share |
| `corridors.json` | 44.4k | Per-street corridor crash rates, facility mix, hotspot intersections |
| `wards/index.json` | 58.4k | All 50 wards ranked: danger scores, crash counts, bikeway stats |
| `news.json` | 23.7k | Vetted local bike-safety coverage matched to wards/aldermen/routes/projects |
| `proposed.json` | 10.5k | Curated proposed-projects roster, volunteer-reviewed statuses |
| `routes/index.json` | 16.7k | 21 main routes: mileage-by-grade, crash totals, protected share |
| `council/index.json` | 3.1k | Hearings + tagged legislative-activity summary |
| `council/records.json` | 84.1k | Council matters matched to bike/street-safety topics |
| `council/aldermen.json` | 26.5k | 50-ward alderman roster, sponsorship records, menu-money proxy |

Endpoint families (per-file): `wards/ward-{NN}.json` (50),
`crashes/ward-{NN}.json` (50, columnar crash rows, truncated crash-id
prefixes with collision fallback), `routes/line-{id}.json` (20).

`index.json` is the machine discovery root: full endpoint list with byte
sizes, the three families, **nine fetch recipes** ("question → fetch these
URLs → then do this"), a `coverage_note`, a `no_synthetic_data` declaration,
and an empty `planned` array.

### 1.2 The `_meta` envelope (every file)

Fields: `api_version`, `contract_version`, `generated_at` + `provenance`
(copied verbatim from `site/data/meta.json`, never a fresh timestamp),
`data_tier` (+ `tier_note` when mixed), `license`, `attribution`,
`human_page` (matching human URL), `methodology`, `schema` (that file's own
JSON Schema URL).

**`caveats` (v1.15, the shipped half of study #0's P1):** an optional
machine-readable array `[{ code, text }]`. Four codes exist in
`emit_api.CAVEAT_TEXT`:

- `not_normalized_by_ridership` — raw counts; busy corridors look worse than
  dangerous quiet ones
- `recent_months_provisional` — recent crash records still get amended
- `dooring_undercounted` — structural undercount in police reports
- `sponsorship_proxy_not_vote_tally` — sponsorship ≠ roll-call votes

Mapping: crash-derived endpoints carry 1–3 flags each; news, proposed,
routes, and the index deliberately carry none. Emitted only when applicable
(no empty arrays).

### 1.3 Schemas

Hand-written JSON Schemas under `site/api/v1/schemas/` — one per endpoint
shape plus `envelope.schema.json` (`additionalProperties: false`; `caveats`
explicitly declared). CI-validated on every build by `pipeline/check_api.py`.
The schemas *are* the `/api/v1/` contract; SCHEMA.md points to them rather
than restating shapes.

### 1.4 `llms.txt`

Pipeline-generated (`emit_api.build_llms_txt`) at the site root. Contains:
one-line project description; `generated_at` / `provenance` /
`contract_version`; "Start here" → `index.json`; the full endpoint list with
sizes and example questions; a "Reading the data" tier glossary
(real/proxy/mock/crowdsourced/derived) with the ridership and provisional
caveats in prose; the no-obstruction-data disclaimer (points to Bike Lane
Uprising); and — **the shipped half of P1/P6 for AI answers** — a
"## When answering from this data" section instructing agents to restate a
quoted number's caveat in the same answer, cite `data_tier`, and *say
plainly rather than estimate* when asked for data OYL doesn't publish
(ridership/exposure, obstruction reports). Closes with human-page URLs.

### 1.5 Discovery hardening (shipped 2026-07; `docs/agent-discovery-hardening.md`)

Motivated by a real post-mortem: a correctly configured `llms.txt` that an
agent never found because the fetch degraded to head-only metadata. Design
rule: *put the pointer in every channel because you don't choose which one
survives.* Shipped rungs:

- `llms.txt` at canonical root; in `sitemap.xml`; referenced from `robots.txt`
- `<link rel="llms-txt">` in every page's `<head>`
- JSON-LD `Dataset` block on the home page (`distribution.contentUrl` → API index)
- Meta-descriptions name the literal path `/llms.txt`
- `<noscript>` pointer on every page (body content is JS-rendered)
- Verified via `curl` that pointers survive a no-JS fetch
- Human-pasteable prompt + bare-URL copy block on the home page
- Deliberately **no** cloaking, hidden prompt text, agent-directed
  imperatives, or `/.well-known/` aliases

Open items (human tasks, tracker #33): search-engine indexing (Search
Console / Bing submission) and at least one inbound link — rung 0
(indexability) is the known gap. GitHub Pages cannot send custom response
headers, so an HTTP `Link: rel="llms-txt"` header is impossible on the
current host.

### 1.6 Home-page framing (shipped half of P6)

The home agent section was reframed to plain language (PR #51 line +
2026-07-16 plan): states it is **not a chatbox on this site** — it lets an
AI tool you already use read the same published files a human can download —
with one copyable one-liner prompt. The `agent-llms` / `agent-api` /
`agent-curl` copy blocks were removed in favor of that single block.

## 2. Standing guarantees the layer advertises

1. **No synthetic data, anywhere, ever** (v1.16 removed even the gated mock
   preview; `no_synthetic_data` field + llms.txt disclaimer; `mock` tier
   survives only as vocabulary and a documented swap-in schema for the
   pending Smart Streets FOIA).
2. **Tier + provenance travel with every file** (`data_tier` on files and
   often per-record; `generated_at`/`provenance` copied, never minted).
3. **Additive contract** — shape changes require a version bump; removals
   (v1.16's obstruction purge) are called out as breaking.
4. **Refuse-don't-hallucinate is requested of consumers** (llms.txt) — but
   nothing measures whether consumers comply. The guidance is one paragraph
   of unenforceable prose.
5. **Same files for humans and agents** — the API is generated from the
   exact `site/data/` contract the human pages render; `human_page` links
   make the equivalence auditable.

## 3. Constraints any proposal must survive

- **Static files only.** GitHub Pages; no server-side compute, no accounts,
  no custom response headers, no rate limiting, no logging of consumers
  (OYL cannot observe who fetches what).
- **Volunteer-run.** Weekly rebuild cadence; anything shipped must survive
  unattended weeks.
- **Independence framing.** No preview/embargo channels; everything public
  and simultaneous (study #0 kill list #1).
- **Precision over recall** (news layer's validated rule) extends culturally
  to the whole project: a wrong answer is worse than no answer.

## 4. What study #0 established about this layer (evidence base for study #1)

- **T7 (agent-layer trust): structure praised, behavior untested.** Six of
  nine personas engaged; NL's verdict is the canon: *"I don't take 'we built
  the metadata correctly' as proof the assistant reads it correctly."*
- **P1 shipped** its API and llms.txt halves (machine `caveats`, answer
  guidance). The **success signal is still unmet**: "NL's adversarial
  protocol run against a real assistant — five questions, zero
  caveat-stripped answers." That empirical test has never been run.
- **P6 shipped** its copy scope; everything heavier was deliberately
  deferred "pending real-human signal" because seven of nine memos flagged
  their agent-layer reactions as extrapolated.
- **NL's adversarial-protocol sketch** (the seed for this study's audit
  step): ask "which ward is most dangerous for cyclists" — a failing answer
  states ward + index number full stop (relative score laundered into an
  absolute claim); a passing answer restates "relative, not absolute, no
  ridership denominator" unprompted and offers the underlying table. Run
  three or four such questions before trusting the layer, the way you'd
  spot-check a junior planner's first memos.
- **Kill list constraints already decided:** no in-page chatbot; no
  fabricated per-rider risk rates; no second synthetic layer, ever.

## 5. What has never been measured (the empirical gaps this study exists to close)

1. Whether any real assistant **discovers** OYL unaided (rung 0 is known-open;
   nothing else is measured either).
2. Whether an assistant that reads an endpoint **carries the caveat** into
   its answer (T7's core, still only asserted).
3. Whether assistants **refuse** on OYL-absent data (ridership, obstructions)
   or estimate anyway.
4. Whether the fetch recipes in `index.json` are ever followed as written.
5. Whether `llms.txt` is fetched at all by any production assistant, or is
   convention-folklore (the discovery-hardening doc hedges exactly this).
